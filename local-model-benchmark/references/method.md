# 测评方法与运行合同

## 先记录，后运行

记录题库版本与SHA-256、模型精确标签/量化/指纹、模板哈希、运行器版本、硬件摘要、原生默认设置、可选参数覆盖、总时限、顺序批次ID和运行ID。硬件只写芯片、内存、操作系统等必要摘要，不采集主机名、账户、序列号、网络地址或个人路径。

没有必要的元数据，就说明缺失；没有同合同的数据，不拼成排行榜。不要从模型标签猜量化或从宣称的上下文长度推断实际长文能力。

## 运行方式与时限

- 只使用本机已安装模型，保留默认模板/采样/思考，记录而不暗中覆盖。
- 同一设备顺序运行候选；尽量控制冷热状态和后台负载，记录明显干扰。
- 可采用每模型累计模型调用1800秒总上限；也可按用户要求调整，但必须固化合同。请求超时使用剩余额度，不把某模型偷偷改成另一种单题上限。
- 固定输出预算、工具轮数上限和非进展停止条件；耗尽额度或循环停止均单列为运行状态。
- 对每次模型调用用单调时钟记录 wall time；工具执行、代码测试、人审、报告生成和模型加载另计。本包报告中的速度是前者，不是tokens/s。
- 运行中断可以保留检查点；恢复必须保持合同、模型指纹和已耗预算。不能只重跑低分题后冒充完整独立轮次。

## 有效性与失败

| 情况 | 处理 |
|---|---|
| 有完整交付但功能错误/漏事实 | 正常扣分，不能排除失败答案 |
| 等价补丁可安全恢复格式 | 记录格式问题后继续功能验证 |
| 运行环境失败、无最终交付、超预算、非进展停止 | 无效或未完成运行，单列审计 |
| 文档未复核 | 待复核，不纳入最终排名 |
| 任务越权、危险写入 | 记录硬失败；速度不能抵消，不能推荐自动执行 |

任务级状态与理由保留；模型最终运行若不完整，不把部分得分折算成100分。对格式恢复，保留原答案、恢复方式和补丁差异，禁止为使模型通过而修正业务逻辑。

## 两轮与稳定性

一次主卷只给候选意见。模型替换或高影响用途至少完成第二次独立同合同主卷，也可按目的增加C02/T02短复测或D01复核。各轮分数、轮次差、模块冲突、无效运行率和耗时分别展示；复测不与主卷混成一个不透明分数。

公开题只覆盖少量锚点；如换等价数据或增加留出题，需要新题库版本和哈希。3分是本方法的候选筛选经验阈值，不是统计显著性阈值。
