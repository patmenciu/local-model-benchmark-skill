# 本地模型能力测评

这是方法型 Skill，不附带自动运行模型的宿主。使用当前环境已有且获准的本地适配器、隔离代码环境与内存工具宿主；缺少条件时先报告可完成范围和缺口，不能伪造已运行结果。

## 先确定比较合同

与用户确定模型的精确标签、目标用途、设备、预算和复测范围。只测试已安装的模型，不自动安装依赖、拉取模型或切换云端。

默认只使用 [examples/synthetic-tasks.json](examples/synthetic-tasks.json) 内的新写虚构材料。不要扫描本机资料；个人文件、历史会议、日志和原始模型对话不是默认输入。此公开题库与历史文章题库不同，不可沿用文章分数。

新测评先读 [references/method.md](references/method.md)，固定题库哈希、设备、顺序批次、模型指纹、运行合同与时限，再顺序运行各模型。不要为了快而统一关闭默认思考。需要限时时记录实际合同，禁止把限时与不限时结果混排。

## 执行与评分

运行任务前读 [references/task-contracts.md](references/task-contracts.md)。只把该题的 `prompt`、该题虚构材料及必要工具 schema 发给被测模型；不要把评分锚点、其他模型答案或历史排名发给它。

编程题的代码先保存为待检答案，只有在用户批准的隔离环境里才能应用和测试；普通临时目录不能被称作沙箱。工具题仅操作虚构内存状态，保留完整调用轨迹；不得连接真实系统。

评分时再读 evaluator-only [references/evaluator.md](references/evaluator.md)。功能、格式可恢复性、运行有效性和副作用分开记录；不要把解析器错误伪装成能力零分，也不要把真正的功能失败当作无效运行排除。

D01先核事实与来源（12分），再对匿名答案做离线内容复核（8分），记录证据、争议和锁分状态。规则与语义复核冲突时做敏感性分析，不默默改分。

## 结果与建议

结果格式和离线命令见 [references/result-format.md](references/result-format.md)。质量100分与累计模型调用时间分别报告；总耗时、首字、吞吐、加载和人工复核不可混称。缺失交付、运行错误、硬失败和未锁分单列，不伪装成完整排名。

一次主卷仅筛候选。分差3分以内、模块结论冲突、模型替换或高影响用途，至少补充一次独立复测；复测分数与波动单列，不把不同题库、参数或诊断配置平均。

按用户任务推荐：质量先过关，再比较等待时间、模块短板和完成情况。仍未做过的真实业务、长会话、并发、内存或安全验证应明确列出。Skill 不授权替换模型配置、发布成绩或上传答案。
