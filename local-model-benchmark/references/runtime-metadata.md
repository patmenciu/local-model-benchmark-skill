# 运行时版本、模型身份与能力记录

## 为什么要记录精确运行条件

模型标签、底层权重、量化、推理引擎与设备优化可能分别变化。近期 Ollama 发布记录持续包含模型支持、MLX 与 llama.cpp 更新；因此，版本更新后不能只沿用旧标签和旧分数。参考：[Ollama Releases](https://github.com/ollama/ollama/releases)（查阅日期：2026-11-08）。

这是可移植的测评流程，不固定某一天的模型榜单。每轮从被测机器的本地运行器读取当前可确认的资料；不为“查最新”而自动联网、更新软件或拉取模型。若使用者另行授权联网查型号信息，注明检索日期和官方来源，并把目录宣传与本机实测分开。

## 每轮记录的运行快照

尽可能记录：

- 模型提供方/运行器、精确模型标签、模型摘要或指纹、参数规模、量化格式与值；不能读取的字段填 `unknown`，不从标签猜测。
- 推理后端及其版本、模板/运行器版本、模型运行时参数，以及与默认设置不同的覆盖项。
- 芯片/加速器、统一内存或显存容量、系统版本；仅需可比较的摘要，不记录主机名、用户名、序列号、网络地址或本地路径。
- 本次确实覆盖的能力与协议：纯文本、工具调用、结构化输出、视觉、音频等；只测实际合同里的能力，未测项目写 `not tested`。模型卡、运行器页面或 API 声明的支持仅作能力发现线索，不作为测评分数或通过证据。
- 题库和模板摘要、完整运行合同、运行次序与冷热状态、开始/结束时间、有效性及中断原因。

不要把一次模型别名解析结果当作永远不变的权重身份。若运行器不提供摘要，注明无法确认，并保留当次标签及本机运行器版本。缺失字段不应阻止报告，但需标明相应结果可比性受限。

## 速度口径

将模型加载/冷启动、首字延迟、提示处理、生成、工具执行与人工复核分开记。比较总回答时间时，在相同设备和合同下固定或平衡冷热顺序；分别报告冷启动与暖运行，不把预加载的一方与冷启动的一方直接比较。若本地运行器只提供总调用时长，就按总调用时长报告，不推算首字延迟或 tokens/s。

每次版本变动后的回归至少重跑目标用途相关题目；如需改全量排行榜，应以同一套合同重跑全部候选。不同引擎、模型摘要、量化、题库或计时定义不可直接混为同一排名。记录这些变化，用于解释结果，不自动归因于模型权重本身。

## 安全与范围

只对题库中的虚构任务运行。版本发现阶段只查询用户明确指定的本地运行器可见元数据；不得扫描其他本地资料，不得自动探测系统或发送提示到远程模型。能力信息无法离线确认时保留为未知，不绕过工具或网络限制。
